# 🎓 Thesis Supervisor Finder

A backend-driven web application that helps computer science students find suitable thesis supervisors and topics through profile management and a recommendation system.

The platform enables students to explore available topics, match them with their interests and completed courses, and allows supervisors to manage thesis offerings in a structured system.

---

## 🛠 Tech Stack

- **Java**
- **Spring Boot (Web, Validation, Thymeleaf)**
- **Spring Security (OAuth2)**
- **PostgreSQL / H2**
- **Spring Data JDBC**
- **Gradle**
- **Docker Compose**
- **JUnit & Mockito**
- **ArchUnit (Architecture Testing)**
- **JaCoCo / Checkstyle**
- **CommonMark + OWASP HTML Sanitizer**

---

## ✨ Key Features

- GitHub OAuth-based authentication
- Role-based access control (**STUDENT / SUPERVISOR / ADMIN**)
- Student profile with interests and completed courses
- Supervisor profile with thesis topic management
- Topic recommendation system based on interests and course overlap
- Markdown-based topic descriptions with XSS-safe sanitization
- Admin dashboard for role management
- Clean Onion architecture with enforced boundaries

---

## 🔐 Authentication & Authorization

The application uses **GitHub OAuth2 login** via Spring Security:

- Users authenticate via GitHub
- Roles are assigned dynamically (**STUDENT / SUPERVISOR / ADMIN**)
- Admin privileges configured via application settings

### Authorization

- Method-level security enforced using `@Secured`
- Role-based endpoint protection:
  - Students → browse & match topics
  - Supervisors → manage topics
  - Admins → manage roles

---

## 🧠 Matching System

A core feature of the platform is the **topic recommendation system**:

- Matches topics based on:
  - Overlap between **student interests**
  - Overlap between **completed courses** and **topic requirements**
- Topics are ranked by relevance using set-based matching

👉 Demonstrates practical application of domain logic in a real use case.

---

## 🏗 Architecture

The application follows **Onion Architecture**:


Domain → Application → Infrastructure → Web


### Design Principles

- **Domain-driven structure** for core business logic
- **Clear separation of concerns**
- **Dependency rule enforced via ArchUnit tests**
- Controllers, services, and repositories are strictly layered
